# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the App

```bash
# Activate venv and run
source venv/bin/activate
python src/app.py
```

## Building

```bash
pip install -r requirements.txt
pyinstaller lp.spec
```

CI builds are triggered by pushing a `v*` tag or via workflow_dispatch. Builds run on Linux (ubuntu-22.04), macOS, and Windows using Python 3.12.

## Architecture

PyQt5 desktop music player ("lp"), v2: the old mini mode is the main window — square album art with a floating control panel, the library and lyrics as side panes. Version lives in `src/version.py` (About dialog + `lp.spec`).

```
App (QMainWindow, frameless; optional always-on-top)
└── root_stack (QStackedWidget, central widget)
    ├── stage: library_pane | player | lyrics_pane
    │     library_pane: mode tabs / nav row (‹ title, Now playing) /
    │                   pages: left_stack (folder | podcast | radio | favorites) ⇄ album_view
    │     player: AlbumArtLabel + floating ControlPanel (hover, idle-hide)
    │     lyrics_pane: track title + lyrics_widget
    └── max page: MaxView (large art + borrowed tracklist/lyrics)
```

**`app.py`** — QMainWindow orchestrator. Owns all top-level widgets, wires signals between them, manages theme/settings/shortcuts, and the four content modes (music/podcast/radio/favorites — the library pane's mode tabs swap `left_stack`). Appearance settings (theme/accent/font size/opacities) are restored in `__init__` *before* the one initial `apply_theme` — applying light first and re-applying dark in `_restore_state` hit a Qt quirk where the second pre-show stylesheet skipped repolishing some subtrees. **Window geometry** (`_set_side_panes`, `resizeEvent`, `_pin_art_width`): in a normal window the art column is pinned square (`player.setFixedWidth(height - 2)`, inside root_stack's 1px border); opening a pane widens the window by `max(PANE_MIN_W, side // 2)` instead of squeezing the art, with a compensating x-shift for the left pane (clamped to the screen) so the art stays under the cursor; with no panes open, `resizeEvent` keeps the window square by following whichever edge is dragged. `_resizing_self` guards programmatic resizes/`restoreGeometry`. Maximized/fullscreen windows unpin and just reflow. Pane visibility is tracked in explicit `_library_on`/`_lyrics_on` flags. **Mode tabs/keys** (`_set_mode`): a new mode opens the pane on its library page; re-picking the active mode toggles the pane (closed → library page; tracks page → library; library page → closed). **Drill-down**: opening an album (`FolderView.album_opened`, `l` in the eventFilter), feed or collection calls `_drill_to_tracks`; `h`/`‹` call `_show_library_page`; `Tab` flips pages; `4` opens/closes the pane on its tracks page. **Browsing ≠ playing**: the tracklist can show an album other than the playing one; `_update_now_playing_link` shows the pane's "Now playing" button then, and `_show_now_playing` (`n`) relists the playing Album/Playlist from memory. The accent follows the *playing* album (`_on_track_changed`), or the browsed one only while nothing has played yet (preview). The ⋯ menu (`main_menu`: Theme, Preferences, Max Mode, Always on Top, Change Station Art (radio), Help, Quit) pops from the panel's ⋯ button or a right-click on the art; its QAction shortcuts are display-only (`Qt.WidgetShortcut`) — the real keys are QShortcuts. Always-on-top (`_set_on_top`, `Shift+T`) re-shows the window after flipping `WindowStaysOnTopHint`. The accent menu is a live-preview swatch grid (`AccentSwatchGrid` + QWidgetAction): hovering a swatch applies the accent immediately, leaving the grid or closing the menu without clicking reverts, clicking commits; "Custom..." opens a QColorDialog whose currentColorChanged previews live too (revert on cancel). `_update_accent_for_album`/`_on_palette_extracted` only call `apply_theme` when the accent actually changes — a saved per-album accent equal to the current one costs no stylesheet rebuild.

**`library_pane.py`** — `LibraryPane` (left of the art): mode tab buttons (`mode_clicked`; checked state set by App via `set_mode`), a nav row (`‹` back button — tracks page only, elided title, "Now playing" link), and a QStackedWidget of the library page (App's `left_stack`) and the tracks page (`tracks_slot`, where App parents the one AlbumView). Titles: `set_library_title` (mode name) / `set_tracks_title` (album/feed/collection); the shown one follows the page. `LyricsPane` (right): title label (track/station name) over `slot` holding the one LyricsWidget. Both are plain containers in the main window, so the main stylesheet styles their contents — no inline per-widget QSS. Max mode borrows AlbumView/LyricsWidget from the slots and puts them back on exit.

**`quick_switcher.py`** — `Ctrl+K` album switcher: a `QFrame` child of App floating near the top of the window (sized to its rows, repositioned on resize) with a QLineEdit + QListWidget (`NoFocus` — typing never leaves the box; `↑↓`/`Ctrl+J/K/N/P`/PgUp/PgDn move, Enter opens, Esc or focus leaving it — `App._on_focus_changed` — closes). Every query word must appear in "parent name"; word-start hits rank above mid-word ones; at most `MAX_ROWS` (200) shown. The album list is `media_server.LibraryCache` (App's own instance, `self.library_cache` — the same stale-while-revalidate walk the phone uses; a folder is an album if it directly holds audio files), fetched on `_WalkThread` — warmed in `_restore_state`, re-requested on each open (instant once walked; re-walks in the background when stale), never two at once. A pick emits `album_chosen(id)` → `App._open_album_by_id`: switch to music mode if needed, select the folder in the tree, load and drill down.

**`max_view.py`** — Max mode (`Shift+M`, ⋯ → Max Mode, or double-click the stage art) page. Lives permanently on the root stack; listens to `player.art_changed`/`track_changed`. Clicking the max-mode art exits (`art.clicked`). A side column next to the art holds a tracklist pane and a lyrics pane, each independently toggleable (`4`/`5`) and each a reparenting slot that *borrows* the app's single AlbumView/LyricsWidget — attached on enter, returned to `library_pane.tracks_slot`/`lyrics_pane.slot` on exit. The lyrics pane carries its own track-title label (`#max-lyrics-title`) above the lyrics text — font-sizing (`_style_max_mode`'s `font_size + 8` bump) applies to the lyrics pane only. No widget duplication; the stage is untouched behind the stack, and `_pre_max_geometry` restores the window (saved as `stage/geometry` if the app quits from max mode). The side column collapses entirely when both panes are off. Visibility is tracked with explicit `tracklist_on`/`lyrics_on` flags rather than `isVisible()`. A corner `close_btn` exits; left/right arrow keys step through the album's art gallery. Mouse motion reveals its own `overlay_controls.ControlPanel` (with `show_back` and `show_more` — ⋯ opens the same `main_menu`, as does right-clicking the max art; `_on_main_menu_show` relabels Max Mode → Exit Max Mode and hides Always on Top there), auto-hidden after idle via an app-wide MouseMove filter installed only while max mode is showing. Since a borrowed tracklist can hold keyboard focus (VimListWidget swallows printable keys), **Library actions work in max mode through `_drill_to_tracks`**: there it shows max's tracklist pane instead of the (off-screen) library pane, so `Ctrl+K`, `n`, opening a feed/collection all land in max's tracklist; `/` searches the tracklist (the only list on screen). Mode keys `1/2/3/0` (`_mode_key`) and `Shift+T` are ignored in max — no library pane to switch, and flipping window flags would drop fullscreen. `App.eventFilter` intercepts max-mode shortcut keys (`_dispatch_max_key`/`_max_key_map`, incl. `Shift+D`/`Shift+H`) for any widget inside `self._max_view`.

**`overlay_controls.py`** — `ControlPanel` is THE playback control surface: floating over the art on the stage (`player.panel`, with `show_more` → the ⋯ button) and in max mode (`show_back`). Squared-off/boxy (`PANEL_RADIUS`/`BUTTON_RADIUS` near-zero) with a subtle `QGraphicsDropShadowEffect` (QSS has no box-shadow); the *only* round element is the favourite heart (`HEART_RADIUS`). Three rows: title (elided) + favourite heart; elapsed time + `ClickableProgressBar` + total time; `[tracklist toggle]` — shuffle — prev — play/pause — next — repeat — `[lyrics toggle]` — `[back]` — `[⋯]`. Toggle icons on the scrim are white when on and grey (`SCRIM_TOGGLE_OFF`) when off — deliberately not accent: the accent is usually extracted from the very art the scrim floats over, so accent-on-scrim-on-art all but vanishes. The heart stays accent. `set_seek_mode(True)` swaps prev/next for ±30s icons (podcasts); `set_seek_visible(False)` hides skip buttons and the progress row (radio). Repeat is a 3-state cycle (`player.repeat_mode`: off/all/one); shuffle mirrors `FavoritesView.shuffle_btn`, the single source of truth (`App._sync_shuffle_state`/`_sync_repeat_state` push state to every panel). `position_control_panel()` centers the panel along the art's bottom edge, capped to 420px wide.

The panel is styled as a translucent scrim — `set_theme(t, ...)` restyles hover tint from the app's accent. The scrim itself is always dark (white icon/text foreground), independent of the app's dark/light theme. Scrim darkness is user-adjustable (`t['overlay_opacity']`, 0-100, set via `App.set_overlay_opacity`/the "Overlay Opacity..." preferences dialog) through `scrim_alpha()`, floored between `MIN_SCRIM_ALPHA`/`MAX_SCRIM_ALPHA` so text never gets unreadable at low settings; the panel remembers its last-seen opacity across `set_theme` calls that omit it (e.g. an accent-only refresh). `IDLE_HIDE_MS` is the shared auto-hide interval; show/hide/idle-timer logic lives in the host (Player, MaxView), not here.

**`favorites.py` / `playlist.py` / `favorites_view.py`** — Favourites mode (`0`, or the ♥ mode tab). `FavoritesStore` is Qt-free (like play_log): one JSON file (`<appdata>/favorites.json`, atomic writes) holding favourited tracks — metadata snapshotted at favouriting time, so listing/playing never parses audio files — plus playlists that reference favourites by path (unfavouriting removes a song from every playlist). Tracks are hearted/unhearted from the tracklist's right-click menu in music or favourites mode (also "Add to Playlist" / "Remove from <playlist>", offered regardless of favourite status — `add_to_playlist(name, track)` favourites the track first if it isn't already, since playlists only ever reference favourites by path); hearted tracks show an accent-colored heart *icon* in album listings (`AlbumView._apply_heart`/`set_heart_color` — icons, not text glyphs, so they follow the accent; `FavoritesView.set_heart_color` does the same for the All Favourites row, and the context-menu favourite actions carry the icon too). Filled hearts also carry a `QIcon.Selected` variant with an `accent_fg` rim (filled accent heart + outline overlay): on the accent selection highlight — i.e. the playing/selected row — the accent fill vanishes into the background and the rim is what keeps the heart visible. Favouriting also works directly from the currently-playing track via any mode's `ControlPanel` heart button (stage and max panels — `App._toggle_current_favorite`/`_sync_favorite_heart` keep both, plus the tracklist row, in sync regardless of which one triggered the change), and from the phone web client (`media_server.py`'s `/api/favorite`). `FavoritesView` (left pane) lists All Favourites + playlists (create/rename/delete via context menu, `l`/Enter loads a collection into the tracklist), and owns the checkable Shuffle button — the single source of shuffle state (`s` toggles it from anywhere, incl. max mode). `Playlist` is the Album-like container the tracklist/player play from; because its tracks span albums, App points `playlist.path`/`.art` at the *current track's* folder on each track change, so lyrics caching and per-album accents key exactly as if that album were playing, and shows the song's `cover.jpg` alone (never the folder's full art gallery). Playlist plays never overwrite `last_album` session restore, and play-log records work unchanged (album_id comes from the track path). Album-art actions (Change/Add/Find Album Art) are blocked with a message (`App._warn_if_playlist_art`) rather than silently no-opping (or, for "Change Cover Art...", writing into the wrong album's real folder) when a Playlist is the active `player.album`.

**`bg_threads.py`** — Keep-alive registry for superseded background QThreads. Dropping the last reference to a *running* QThread aborts the whole process ("QThread: Destroyed while thread is still running"), so anything that restarts background work per user action (album loads, lyrics fetches, palette extractions, art decodes) disconnects the old thread's result signal and calls `bg_threads.retire(old)` instead of `wait()`ing (which used to freeze the UI up to 2s per quick track switch) or replacing the reference outright (which was the rapid-album-switching crash). `retire()` relies on the real `QThread.finished`, so worker subclasses must NOT shadow it with a custom signal named `finished` (renamed: `AlbumLoadThread.album_ready`, `PaletteExtractThread.palette_ready`, `_ImageLoadThread.image_ready`). `wait_all()`/`any_running()` back the shutdown path: `closeEvent` gives threads a short bounded wait, and if anything still lingers, `main()` exits via `os._exit` (settings/play-log already flushed) rather than let interpreter teardown destroy a running thread.

**`player.py`** — The stage and playback. `build_gui` is just the `AlbumArtLabel` filling the column plus `self.panel` (a `ControlPanel`) floated over it: shown on mouse movement, hidden on leave/after `IDLE_HIDE_MS` idle. Mouse-move goes to whichever child is under the cursor, so the art, the panel and all their children get mouse tracking with the Player as event filter — scoped to the stage, never an application-wide filter (it's the main window now; an app-wide filter would see every event in the app all the time). The same filter makes a left-press on the art start a system window move (frameless window; skipped when maximized/fullscreen), a double-click emit `art_double_clicked` (→ max mode) and a right-click emit `art_menu_requested` (→ ⋯ menu). `progress_bar`/`track_progress_label`/`track_length_label`/`prev_track_button`/`play_button`/`next_track_button` are aliases onto the panel's widgets, so podcast/radio's control swapping (`App._set_podcast_controls`/`_set_radio_controls`/`_set_music_controls`: reconnect `.pressed`, `panel.set_seek_mode`/`set_seek_visible`) works against the same names; `_set_play_icon` drives `panel.set_playing`. Uses `just_playback` (requires `play()` before `pause()`/`seek()` will work). **Art follows playback, not browsing**: `_art_album` is the album whose art is showing; `play()`/`load_track()` call `_follow_album_art(album)`, which loads a real `Album`'s art only when it differs (Playlists and podcast feeds manage their own art via App); `set_art`/`set_art_path` clear `_art_album`. `play()`/`load_track()` only highlight the tracklist row when the tracklist shows the playing album (`album.same_listing`). Artwork files are decoded off the UI thread (`_ImageLoadThread`) — `set_art_path(path)`/`_load_art_async` are token-guarded so a stale decode can never land over a newer request. Shuffle (`player.shuffle`): `next_track` draws from a shuffled bag of remaining indices (each track once per cycle; auto-advance stops when the bag empties, manual `>` refills), `prev_track` walks back through the actual play order. Repeat (`player.repeat_mode`, `'off'`/`'all'`/`'one'`): `'one'` replays the current track on `track_finished`; `'all'` keeps auto-advancing (and reshuffling) past the album's last track. Emits `track_changed`, `track_finished`, `art_double_clicked`, `art_menu_requested(QPoint)`, `art_changed(QPixmap)`, and `play_state_changed(bool)`. All artwork must go through `player.set_art(pixmap)` or `player.set_art_gallery(paths)` so listeners stay in sync. The gallery is the album folder's images (cover first); `step_art(±1)` scrolls it, and every `AlbumArtLabel` registered via `register_art_label()` (stage, max view) gets hover arrows wired to it. `register_progress_display()` mirrors progress onto max mode's panel. Progress/lyrics tick on a 200ms QTimer. SVG icon rendering is memoized by (name, color, size).

**`art_label.py`** — `AlbumArtLabel`: aspect-ratio-preserving art display. Downscales oversized sources (>1200px) once on load, caches a display-sized copy, and refreshes it on a 120ms debounce — no full-res repaints, no graphics effects. Non-square art (back covers, inserts) is always letterboxed within the label's square footprint, never cropped (the old `square=True` center-crop is gone — full images matter now that phone photos land in the gallery). Has built-in prev/next hover arrows for art galleries (`set_nav_enabled`) — shown only while hovered, hidden whenever the application deactivates.

**`theme.py`** — One font for the whole app: Inter, bundled in `src/fonts/` (Regular + Bold, OFL) and registered by `resolve_fonts()` at startup (system-sans fallback if missing). One size scale (`SIZES`/`DEFAULT_SIZE`) — the Text Size dialog and `Ctrl+=`/`Ctrl+-` step everything together. LIGHT/DARK token dicts (`bg`, `bg_elevated`, `fg`, `fg_dim`, `hairline`, `hover`, `accent`, `accent_fg`, plus legacy aliases for the dialogs). `build_qss()` produces ONE consolidated stylesheet applied once to the main window in `App.apply_theme` (theme/accent/font changes only). Focused-pane highlighting uses the dynamic `paneFocused` property on the tree/list views with `[paneFocused="true"]` selectors — focus changes repolish only the affected views, never regenerate QSS. `dialog_qss()` styles the dialogs. `track_list_qss()` factors out the `#track-list`/`#search-bar` rules. `minimal_scrollbar_qss()` is a thin, fading, *square-cornered* scrollbar (both orientations — horizontal scrolling gets the identical treatment) used by the tracklist (always — it's folded into `track_list_qss()`), the lyrics pane in max mode (see `lyrics_widget.py`), and the artwork-finder scroll areas; the base stylesheet hides scrollbars everywhere else. Accent color is woven into hover states everywhere (`accent_hover`, a ~9%-alpha tint, replaces flat grey hover on mode tabs and list/tree items) but is never trusted as literal text color at face value — `App.apply_theme` also computes `accent_text` (accent re-contrast-checked at ~4.5:1, stricter than the 3:1 used for `accent` itself) for the few spots that render it directly as foreground text (see `lyrics_widget.py`).

**`album.py`** — Parses a folder into a list of Track objects using mutagen (`os.scandir` listing — file types come from the directory entries, no `stat()` per file on a NAS). `refresh_art()` scans the folder for artwork: `art` is cover.jpg, `art_list` is every image (cover first) — the scrollable gallery. `AlbumCache` is a thread-safe LRU of parsed Albums validated by folder mtime (one `stat()` per hit; in-place tag edits don't bump the mtime — accepted staleness): `album_view._album_cache` backs desktop album opens (revisits no longer re-run mutagen) and the media server keeps its own instance. `same_listing(a, b)` compares tracklist containers (identity, or two parses of one folder).

**`track.py`** — Plain data class for track metadata. All string fields are `str()`-converted in `__init__` to avoid mutagen lazy objects.

**`folder_view.py`** — Filesystem folder browser using QFileSystemModel. Filters to show only directories. Clicking an album folder loads it into AlbumView and emits `album_opened` (App drills the library pane down). `_has_music` runs on the UI thread per click, so it uses `os.scandir`, name test first, stopping at the first hit. Has context menu for "Open folder" via platform file manager.

**`album_view.py`** — Tracklist. Long titles elide on one line (full text in tooltip); `setUniformItemSizes(True)` keeps large lists cheap. Loading an album selects row 0 so keyboard focus always lands on a visible highlight (App's `_focus_tracklist` also guarantees a selected row on Tab/`l`/`4`). Shows either an Album (`_on_album_loaded` after a background load, or `show_album` for an already-parsed one; favourites get accent heart icons) or a Playlist (`load_playlist`, labels carry the artist). Right-click a track for favourite/playlist actions (when `fav_store` is attached; emits `favorites_changed`) and "Look Up Chords / Tab", which opens the default browser (via `QDesktopServices`) with a web search — no scraping, no API key.

**`progress_bar.py`** — ClickableProgressBar with click-to-seek and drag-to-scrub. Emits `seek_requested` (during drag) and `start_playback` (on release) signals.

**`music_icon_provider.py`** — Custom QFileIconProvider that hides folder icons (returns transparent pixmap) to keep the folder tree visually clean.

**`lyrics_widget.py` / `lyrics_fetcher.py`** — Lyrics display with synced scrolling; fetches from LRCLIB API, prefers synced `.lrc`, caches in `album/lyrics/`. The disk-cache check (and its `mkdir`) happens inside `LyricsFetchThread.run()`, never on the UI thread — the album folder is on a possibly slow NAS, and `App._on_track_changed` used to stat+read it synchronously per track change. Superseded fetches are disconnected and retired via `bg_threads` (see above), never `wait()`ed on. QTextBrowser-based: one QTextBlock per line/segment, active-line highlight via QTextCharFormat on only the changed blocks, auto-scroll from the block's measured y-position (accurate with wrapped lines). The active-line/timestamp color comes from `theme['accent_text']`, not `theme['accent']` — see `theme.py` — so it stays readable regardless of the chosen accent hue. Podcast descriptions get clickable timestamps and segment highlighting. Radio now-playing goes through `set_status_html()`. In max mode the pane is short enough that scrolling isn't obvious, so App layers in `theme.minimal_scrollbar_qss()` (a thin, low-alpha handle that fades into the background) on top of the per-widget style override used there; the base app stylesheet hides scrollbars everywhere else.

**`artwork_finder.py`** — Artwork search dialog. iTunes Search API for covers, saved as `cover.jpg` (overwritten in place, streamed to disk). With `extra=True` ("Find More Album Art...") it saves to the next free `art_N.jpg` instead and *also* searches Discogs (`DiscogsSearchThread`, unauthenticated, ~4 requests/search against a 25/min limit) — Discogs releases carry collector scans of backs, labels, gatefolds and inserts, shown in their own section below the iTunes covers. In this `extra` mode each result row shows a checkbox instead of an immediate-save button; picks persist in `_selected` (keyed by URL) across repeated searches, and "Save Selected" downloads them all in one queued batch before closing the dialog — so you don't need a fresh dialog open per image. The non-extra ("Change Cover Art...") dialog keeps the original single-click-save-and-close flow. "Add Album Art..." (App) copies local image files into the album folder. All paths refresh the player's gallery. `finder_dialog_qss()` is the one stylesheet for these dialogs (rows opt in via object names: `#result-row` with accent-tint hover, `#row-thumb/-title/-detail`, `#accent-btn`, `#section-header`, `#status-label`, accent checkboxes, minimal scrollbar); radio's `StationArtDialog` reuses it, and in multi-select mode the whole row is a click target for its checkbox.

**`color_extract.py`** — Extracts a palette from album art (QImage pixel sampling, HSV binning) and picks the most readable accent color using WCAG contrast ratios. Always runs in `PaletteExtractThread` — never on the UI thread; the last palette is cached for menu rebuilds.

**`vim_views.py`** — VimTreeView/VimListWidget with vim-style j/k/h/l navigation, `/` search, and Enter-to-open. Consumes printable keys to prevent type-to-search.

**`play_log.py`** — Listening history: append-only JSONL (`<appdata>/plays.jsonl`, e.g. `~/.local/share/lp/music-player/` — deliberately Qt-free path logic so App, server threads, and the CLI agree) plus the pure `aggregate()` behind `/stats`. A play counts by the Last.fm rule (≥50% of the track or ≥4 min of *actual* listening): `Player._listened` ticks in `check_track_pos` only while playing (seek-immune), and `Player.flush_listen()` — first statement of `play()`/`load_track()`, plus once in `closeEvent` — emits `listen_ended(track, seconds)` which `App._on_listen_ended` gates (music only) and appends. Phone plays arrive via `POST /api/played` (same rule, client-side accumulator in webclient/app.js, single-fire beacon). `python src/play_log.py --stats 2026` / `--fake N --out F` for testing. Stats served at `/stats` (Preferences → Listening Stats... opens it; starts the server one-shot without flipping `server/enabled`): year-picker page, top artists (photos via `/api/artist_image` — Deezer, keyless, cached in `<appdata>/artist_images/` with `.miss` negative-cache), album grid from `/api/art`, bar charts in `#cc7511` (validated vs `#121212`; the app accent `#f2932c` is out of the dark-mode lightness band for data marks). Drill-down: `aggregate()` takes filters `period` (ISO-timestamp prefix: `YYYY` / `YYYY-MM` / `YYYY-MM-DD`), `artist`, `album` (an `album_key()` — the album id, or `name:artist/album` for id-less plays), `title`, plus `limit` to lift the top-N caps; `/api/stats` passes them through from the query string and `/api/history` returns paged individual plays (`play_log.history()`, newest first) for the same filters. The page routes on the URL hash (`#period=2026&artist=…`, `#list=artists|albums|tracks|new`) so back/forward and bookmarks work; every artist/album/track/month/day/calendar cell links to its own view. Records without `src` count as `other` in `by_source` (pre-src logs and the Subsonic tee).

**Remote access deployment note**: the server itself is plain HTTP. HTTPS (and off-LAN access) comes from Tailscale on the host — `tailscale serve --bg 8642` proxies `https://<machine>.<tailnet>.ts.net/` → `127.0.0.1:8642` (tailnet-only, persists across reboots; `tailscale serve --https=443 off` disables). The HTTPS origin matters beyond transport: browsers treat the Media Session API (lock-screen art/controls) as secure-context-only, and the client additionally reports `mediaSession.playbackState` on play/pause — without it a paused session is treated as abandoned and the lock-screen play button reverts to the phone's previous media app. The phone must be on the tailnet (Tailscale app connected); plain-LAN http URLs still work for playback but with second-class lock-screen behavior.

**`media_server.py` / `server_dialog.py` / `webclient/`** — Remote Access (Preferences menu): an embedded stdlib HTTP server (`ThreadingHTTPServer` on a daemon thread — plain `threading`, never Qt; handlers only read disk via `Album`) that streams the library to a phone over LAN/Tailscale. Binds `0.0.0.0:<server/port>` (default 8642); auth is a short shared token as `?token=` (query param because `<audio src>` can't set headers), compared with `hmac.compare_digest`. Album ids are POSIX relpaths under `library_root`, containment-checked by `_resolve()` — absolute paths never cross the wire. `GET /api/favorite`/`POST /api/favorite` (query/body: `id`, `n` — album id + tracknumber) read/toggle favourite status against the same `favorites.json` the desktop app uses (`FavoritesStore`, constructed fresh per request rather than shared across threads); the track's real path is resolved server-side from `Album(folder).tracklist` by tracknumber, never trusted from the client. `POST /api/art_upload` (query: `id`, optional `mode=extra`; body: raw image bytes) saves a phone-camera photo as album art through the same `_resolve()` containment check — default overwrites `cover.jpg` in place (any stale cover under a different extension is removed so it doesn't linger in the folder scan), `mode=extra` picks the next free `art_N.jpg` (mirrors `artwork_finder.py`'s desktop naming; the web client always sends `mode=extra` — phone photos are additional art, never the cover); responds with the refreshed `art` list so the client can redraw immediately. `POST /api/lyrics_fetch` (body: `id`, `n`) is the POST twin of the read-only `GET /api/lyrics`: it mirrors `lyrics_fetcher.py`'s LRCLIB search logic and cache naming exactly (re-implemented Qt-free — importing the real one would pull PyQt5 into the server), writing into `<album>/lyrics/` where the desktop reads it; a `_LYRICS_FETCH_LOCK` serializes searches and re-checks the cache under the lock. `/api/albums` is a stale-while-revalidate cached `os.walk` (a big NAS library can take ~35s to walk; requests never wait once warmed — `start()` pre-warms). `AlbumCache` (from `album.py`; LRU of parsed `Album` objects, validated by folder mtime — one `stat()` per hit) backs `/api/album` and every favourite check/toggle: `Album()` runs mutagen over each track file, seconds on a NAS mount, and the phone triggers a favourite check on *every* track change — re-parsing per request was the web client's main source of sluggishness (in-place tag edits don't bump folder mtime, an accepted staleness). `/api/stream` + `/api/art` do single-range requests (206/416, HEAD parity, 64 KiB chunks, abort-tolerant) — iOS Safari's `Range: bytes=0-1` probe must get a correct 2-byte 206 or audio silently fails — and send `Last-Modified` + `Cache-Control: no-cache`, answering `If-Modified-Since` with a 304 so multi-MB art scans revalidate as header-only round trips instead of re-downloading per album view (no `max-age`: a cover replaced from the desktop shows up immediately).

`webclient/` is a vanilla-JS PWA that is a deliberate port of the v1 mini mode (now the desktop main window). `#stage` is a 3-slot flex container — `#tracklist-pane` | `#center` (art) | `#lyrics-pane` — whose direction flips with orientation: landscape mirrors mini mode exactly (tracklist LEFT of the art, lyrics RIGHT, either/neither/both open), portrait folds the tracklist from the TOP and lyrics from the BOTTOM, one at a time (opening one closes the other; rotating to portrait with both open keeps the tracklist). The panes are in-flow accordions animated from zero width/height — they *push* the letterboxed art, never cover it — each carrying a permanent title label (`#tracklist-pane-title` "Artist — Album", `#lyrics-pane-title` track title, mirroring mini's pane titles); `html`'s background is black so any viewport-chrome sliver reads as letterbox, not a white gap. `#panel` is a CSS/JS port of `overlay_controls.ControlPanel`, absolutely positioned along the art area's bottom edge (capped 420px like `position_control_panel`) and **always visible** — same three rows (title+heart / time+progress+time / `tracks-btn` | shuffle prev play next repeat | `lyrics-btn`), same always-dark scrim (`rgba(20,20,20,.62)` = `scrim_alpha(60)`, theme-independent), same squared-off radii (2px panel / 3px buttons, only the always-accent heart is round), no back button (the drawer covers navigation). The progress bar is a div-based ClickableProgressBar (tap-seek, drag-scrub via pointer capture, commit on release). Shuffle and repeat port `player.py`'s semantics client-side: a bag of remaining indices (each track once per cycle; `ended` stops on an empty bag unless repeat `'all'`, manual next refills) with prev walking the real play-order history, and an off→all→one repeat cycle (`'one'` replays via `playTrack(idx)` so the play beacon re-arms) — both persisted in localStorage (`lp-shuffle`/`lp-repeat`). Only the two corner buttons (`#menu-btn`/`#camera-btn`, the `.chrome` class) auto-hide after 2.5s idle now; the library is a left drawer (rebuilt on open, not per track change — hundreds of rows). The camera button (`<input type=file capture=environment>`) feeds an interactive crop screen (`#crop-screen`): the whole photo fits on screen (the frame is sized by JS to hug the displayed image, so box coords are image coords scaled by one factor) with an adjustable crop box over it — drag inside to move, grab an edge/corner handle to resize; free aspect ratio, starting as the largest centered square (the most likely shape, not a requirement). The handles hang *outside* the box edges and the frame deliberately does NOT clip (`overflow` visible) — the default box already touches the frame, and clipped pixels aren't hit-testable; the outside-the-box dim is the box's screen-wide `box-shadow`, which needs no clipping because the screen behind the photo is pure black (`#crop-cancel` gets `z-index:1` to paint above it). Confirm uploads the cropped JPEG (long edge capped 1600px) via `/api/art_upload?mode=extra` (always additional art, never the cover; the camera button flashes accent to confirm). Lyrics: cached lyrics via `GET /api/lyrics`; on a miss the panel shows "Searching for lyrics…" and asks the server to find them (`POST /api/lyrics_fetch`), with tap-to-retry on failure. Dark by default with a light skin (`body.light`, CSS custom properties in `style.css`, toggled from a drawer button and persisted in `localStorage`) — the accent color (`#f2932c`) and the album-art title scrim (always light-on-shadow, since it sits over unpredictable cover art, not the page) stay fixed across both. The boot placeholder is the app icon (`icon.png`, upscaled). There is deliberately NO offline/downloads feature and NO service worker (reaching the app needs a connection anyway, and lossless albums are too big for Cache Storage) — boot actively unregisters any previously-installed service worker and deletes the old `lp-downloads-v1` cache so stale clients heal themselves. Screen-off album playback = ONE persistent `<audio>` element whose `ended` handler swaps src and replays (recreating the element drops iOS's background-audio session); the Media Session API is feature-guarded (secure-context-only — absent over plain http, playback and browsing still work, just not lock-screen art/controls). `media_server.py` runs standalone for curl testing: `python src/media_server.py --root ~/Music --port 8642 --token test`. App owns start/stop (`_start_media_server`/`_stop_media_server`); autostarts when `server/enabled`, stops in `closeEvent`, follows library-root changes live. Note: `.m4a` files are listed by the walk but produce no tracks (`tracklist_from_folder` has no m4a tag branch), so m4a-only folders 404 — same as the desktop.

**Settings**: `QSettings('lp', 'music-player')` persists theme, accent (global + per-album `album_accents`), text size (`font_size`), overlay panel opacity (`overlay_opacity`, 0-100), window geometry and side panes (`stage/geometry` — falls back to v1's `mini/geometry` on first v2 launch — `stage/library`, `stage/lyrics`, `stage/on_top`), remote access (`server/enabled`, `server/port`, `server/token`), library path, app mode, shuffle, repeat (`repeat`, `'off'`/`'all'`/`'one'`), and per-mode playback positions. Favourites/playlists live in `<appdata>/favorites.json`, not QSettings.

## Key Conventions

- Vim j/k/h/l navigation in folder view and tracklist; h/l in tracklist goes back up to the library page
- Global QShortcuts are suppressed when a QLineEdit has focus
- Side pane visibility goes through `App._set_side_panes` only (it owns the window-widening geometry) — never call `setVisible` on the panes directly; library-pane pages go through `_drill_to_tracks`/`_show_library_page`
- All artwork goes through `player.set_art()` / `player.set_art_gallery()`; theme/accent changes go through `App.apply_theme` (one stylesheet)
- One font (Inter) and one text size app-wide — no per-category font settings
- All source files live in `src/` with flat structure (no subpackages)
- No test suite exists currently
- Dependencies: PyQt5 for GUI, just_playback for audio, mutagen/tinytag for metadata, requests for API calls
