# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the App

```bash
# Activate venv and run
source venv/bin/activate
python src/app.py
```

## Building

```bash
pip install -r requirements.txt
pyinstaller lp.spec
```

CI builds are triggered by pushing a `v*` tag or via workflow_dispatch. Builds run on Linux (ubuntu-22.04), macOS, and Windows using Python 3.12.

## Architecture

PyQt5 desktop music player ("lp") with a nested-splitter layout:

```
root_stack (QStackedWidget, central widget)
├── normal page: toolbar / main_splitter
│     main_splitter (H): left_stack | player | right_splitter
│       left_stack (QStackedWidget): folder_view | podcast_view | radio_view | favorites_view
│       right_splitter (V): album_view / lyrics_widget
└── max page: MaxView (large art + borrowed lyrics widget)

MiniView (separate always-on-top window, toggled with `m`): square album
art + hover controls, optionally the borrowed lyrics widget beside it.
```

**`app.py`** — QMainWindow orchestrator. Owns all top-level widgets, wires signals between them, manages theme/settings/shortcuts, and the four app modes (music/podcast/radio/favorites — the left stack swaps views, the splitters never see mode changes). Appearance settings (theme/accent/font size/opacities) are restored in `__init__` *before* the one initial `apply_theme` — applying light first and re-applying dark in `_restore_state` hit a Qt quirk where the second pre-show stylesheet skipped repolishing some subtrees, leaving the file browser/player column light on dark-mode launches. The toolbar has no library toggle button — the mode buttons double as it (clicking the active mode, or its number key, toggles the library panel and focuses it). The accent menu is a live-preview swatch grid (`AccentSwatchGrid` + QWidgetAction): hovering a swatch applies the accent immediately, leaving the grid or closing the menu without clicking reverts, clicking commits; "Custom..." opens a QColorDialog whose currentColorChanged previews live too (revert on cancel).

**`panel_manager.py`** — `PanelManager` is the single source of truth for panel visibility ('library', 'tracklist', 'lyrics') and remembered splitter sizes. Hiding a panel records its extent; showing it restores that extent while shrinking siblings proportionally, so toggles round-trip exactly. Splitter drags update the remembered sizes live. The whole right column collapses when both its panes are hidden. Toolbar buttons mirror its `visibility_changed` signal (they hold no state). Each app mode remembers its own tracklist/lyrics visibility: `snapshot(mode)` on leaving a mode, `apply_mode(mode)` on entering (first visit gets `MODE_DEFAULTS`: podcast and favorites open the tracklist, radio opens neither; music keeps the session state). `save()/load()` persist to QSettings (`layout/main_splitter`, `layout/right_splitter`, `layout/panel_sizes`, `layout/mode_panels`, `*_visible`). `locked = True` during max and mini mode.

**`max_view.py`** — Max mode (`Shift+M`, or the toolbar's max-mode icon) page. Lives permanently on the root stack; listens to `player.art_changed`/`track_changed`. Entered only via shortcut/toolbar icon — clicking the album art no longer enters max mode (it still exits it, via `art.clicked`). A side column next to the art holds a tracklist pane and a lyrics pane, each independently toggleable (`4`/`5`) and each a reparenting slot that *borrows* the app's single AlbumView/LyricsWidget — attached on enter, returned to `right_splitter` (index 0/1) on exit. The lyrics pane carries its own track-title label (`#max-lyrics-title`, a permanent child of `lyrics_wrap`, not the borrowed widget) above the lyrics text — font-sizing (`_style_max_mode`'s `font_size + 8` bump) applies to the lyrics pane only, not the tracklist. No widget duplication, no settle timers; the normal page is untouched behind the stack. The side column collapses entirely when both panes are off (mirrors PanelManager's right-column collapse). Visibility is tracked with explicit `tracklist_on`/`lyrics_on` flags rather than `isVisible()`, since a pane's own visible-flag reads back unreliably the instant its parent column is hidden/shown too. A corner `close_btn` (top-right overlay, since the toolbar isn't visible in fullscreen) exits back to the normal window; left/right arrow keys step through the album's art gallery. Mouse motion reveals `overlay_controls.ControlPanel` — the same unified hover panel mini mode uses (title, favourite heart, progress bar/time, transport, tracklist/lyrics toggles, back button) — auto-hidden after idle via an app-wide MouseMove filter. Since the panel can have keyboard focus stolen by a borrowed tracklist (VimListWidget swallows printable keys), `App.eventFilter` intercepts max-mode shortcut keys (`_dispatch_max_key`/`_max_key_map`, incl. `Shift+D`/`Shift+H`) for any widget inside `self._max_view` before they'd otherwise be swallowed — mirrors the same defensive interception MiniView's `eventFilter` has always done.

**`overlay_controls.py`** — Two widgets sharing one visual language (squared-off/boxy — `PANEL_RADIUS`/`BUTTON_RADIUS` are near-zero — with a subtle `QGraphicsDropShadowEffect` drop shadow, since QSS has neither `box-shadow` nor `text-shadow`; the *only* round element is the favourite heart, `HEART_RADIUS`):
- `ControlPanel` — the unified translucent hover panel over album art in mini and max mode, built once and reused identically by both (`max_view.py`/`mini_view.py`). Three rows: title (elided) + favourite heart; elapsed time + `ClickableProgressBar` (from `progress_bar.py`) + total time; tracklist toggle, prev, play/pause, next, lyrics toggle, and (mini/max only) a back button. `position_control_panel()` centers it along the art's bottom edge, capped to 420px wide (mirrors `player.py`'s own `controls_container`).
- `HeartOverlay` — one big accent-colored heart (no scrim box, no other buttons) shown over the album art in the *normal-mode* player column only (`Player.eventFilter` on `album_widget`'s Enter/Leave, centered over the art) — favourite/unfavourite the playing track. Tracklist/lyrics toggles live in the toolbar only.

Both are dark scrims (readable on any artwork, light or dark) but accent-aware — `set_theme(t, ...)` restyles hover tint and active/checked icon color (tracklist-on, lyrics-on) from the app's accent, mirroring `App._toolbar_icon`'s dim/fg/accent pattern. The favourite heart is the one exception to that pattern: it's *always* accent-colored (hollow outline unfavourited, filled favourited) rather than dim-until-active, since it's a standalone always-reachable action, not a panel-state indicator — same treatment on the phone web client. Scrim darkness is user-adjustable (`t['overlay_opacity']`, 0-100, set via `App.set_overlay_opacity`/the "Overlay Opacity..." preferences dialog) through `scrim_alpha()`, floored between `MIN_SCRIM_ALPHA`/`MAX_SCRIM_ALPHA` so text never gets unreadable at low settings ("glassy" isn't fully transparent); both widgets remember their last-seen opacity across `set_theme` calls that omit the key (e.g. an accent-only refresh), so a partial-dict call can never silently reset it to default. `IDLE_HIDE_MS` is the shared auto-hide interval; show/hide/idle-timer logic lives in the host view, not here.

**`mini_view.py`** — Mini mode (`m`): a separate frameless, always-on-top window of just the album art. The window stays square (resizeEvent follows the dragged edge); resizing reuses `WindowGrips`, dragging the art moves the window, double-click/Esc/`m` exits. `overlay_controls.ControlPanel` — the same unified hover panel max mode uses — floats over the art, shown only on hover, hidden immediately on leave or window deactivate, and *also* auto-hidden after `IDLE_HIDE_MS` (2.5s) of no mouse movement even while still hovering — done via a QApplication-wide `MouseMove` event filter (child widgets swallow mouse-move before it would ever reach the window's own handlers) that restarts the idle timer and re-shows the panel plus the art's hover nav arrows together. The same app-wide filter also routes KeyPress events for anything focused *inside* the mini window through the key map — the borrowed VimListWidget swallows printable keys, so without this `m`/`p`/`4`/`5` would die in the tracklist whenever it had focus; modifier-sensitive shortcuts (`Shift+H` favourite, `Shift+D` dark mode, `Ctrl+=`/`Ctrl+-` text size) go through separate `_shift_keymap`/`_ctrl_keymap` dicts (`set_shift_key_handlers`/`set_ctrl_key_handlers`) since the plain `_keymap` doesn't distinguish modifiers. The app-wide filter is installed only while the mini window is showing (showEvent/hideEvent) — a permanent app-wide filter would tax every event in the application while mini mode is closed; MaxView scopes its own MouseMove filter the same way. Tracklist and lyrics are independent side panes — tracklist LEFT of the art, lyrics RIGHT — either, neither, or both can be open at once (`_apply_side_layout` widens the window on whichever side(s) are open); each pane carries its own title label above the borrowed widget (`#mini-tracklist-title` shows the album name, `#mini-lyrics-title` shows the track name — permanent children of the wraps, set in `_on_track_changed`), distinct from the ControlPanel's own title (both are kept, by design). Since MiniView is a separate top-level window the main stylesheet never reaches it, so App styles the borrowed AlbumView/LyricsWidget directly (`theme.track_list_qss()`/inline lyrics QSS) each time they're attached; `set_theme()` restyles the shell, the two title labels, and the panel (`ControlPanel.set_theme`). Left/right arrow keys step through the art gallery. Key handling is a Qt-key→callable map supplied by App, so mini mode reuses the app's shortcut behaviors. Geometry and lyrics/tracklist preference persist (`mini/geometry`, `mini/lyrics`, `mini/tracklist`).

**`favorites.py` / `playlist.py` / `favorites_view.py`** — Favourites mode (`0`, or the toolbar heart). `FavoritesStore` is Qt-free (like play_log): one JSON file (`<appdata>/favorites.json`, atomic writes) holding favourited tracks — metadata snapshotted at favouriting time, so listing/playing never parses audio files — plus playlists that reference favourites by path (unfavouriting removes a song from every playlist). Tracks are hearted/unhearted from the tracklist's right-click menu in music or favourites mode (also "Add to Playlist" / "Remove from <playlist>", offered regardless of favourite status — `add_to_playlist(name, track)` favourites the track first if it isn't already, since playlists only ever reference favourites by path); hearted tracks show an accent-colored heart *icon* in album listings (`AlbumView._apply_heart`/`set_heart_color` — icons, not text glyphs, so they follow the accent; `FavoritesView.set_heart_color` does the same for the All Favourites row, and the context-menu favourite actions carry the icon too). Filled hearts also carry a `QIcon.Selected` variant with an `accent_fg` rim (filled accent heart + outline overlay): on the accent selection highlight — i.e. the playing/selected row — the accent fill vanishes into the background and the rim is what keeps the heart visible. Favouriting also works directly from the currently-playing track via the big hover heart over the player-column art (`HeartOverlay`), or in max/mini mode's `ControlPanel` (`App._toggle_current_favorite`/`_sync_favorite_heart` keep every heart button — player column, max panel, mini panel, tracklist row — in sync regardless of which one triggered the change), and from the phone web client (`media_server.py`'s `/api/favorite`). `FavoritesView` (left pane) lists All Favourites + playlists (create/rename/delete via context menu, `l`/Enter loads a collection into the tracklist), and owns the checkable Shuffle button — the single source of shuffle state (`s` toggles it from anywhere, incl. max/mini mode). `Playlist` is the Album-like container the tracklist/player play from; because its tracks span albums, App points `playlist.path`/`.art` at the *current track's* folder on each track change, so lyrics caching and per-album accents key exactly as if that album were playing, and shows the song's `cover.jpg` alone (never the folder's full art gallery). Playlist plays never overwrite `last_album` session restore, and play-log records work unchanged (album_id comes from the track path). Album-art actions (Change/Add/Find Album Art) are blocked with a message (`App._warn_if_playlist_art`) rather than silently no-opping (or, for "Change Cover Art...", writing into the wrong album's real folder) when a Playlist is the active `player.album`.

**`bg_threads.py`** — Keep-alive registry for superseded background QThreads. Dropping the last reference to a *running* QThread aborts the whole process ("QThread: Destroyed while thread is still running"), so anything that restarts background work per user action (album loads, lyrics fetches, palette extractions, art decodes) disconnects the old thread's result signal and calls `bg_threads.retire(old)` instead of `wait()`ing (which used to freeze the UI up to 2s per quick track switch) or replacing the reference outright (which was the rapid-album-switching crash). `retire()` relies on the real `QThread.finished`, so worker subclasses must NOT shadow it with a custom signal named `finished` (renamed: `AlbumLoadThread.album_ready`, `PaletteExtractThread.palette_ready`, `_ImageLoadThread.image_ready`). `wait_all()`/`any_running()` back the shutdown path: `closeEvent` gives threads a short bounded wait, and if anything still lingers, `main()` exits via `os._exit` (settings/play-log already flushed) rather than let interpreter teardown destroy a running thread.

**`player.py`** — Playback controls and album art. Uses `just_playback` (requires `play()` before `pause()`/`seek()` will work). Artwork files are decoded off the UI thread (`_ImageLoadThread`, QImage in a worker → QPixmap on the GUI thread) — covers live on a possibly slow NAS, so the old synchronous `QPixmap(path)` froze the UI on album switches; `set_art_path(path)`/`_load_art_async` are token-guarded so a stale decode can never land over a newer request (`set_art(pixmap)` also bumps the token). Shuffle (`player.shuffle`): `next_track` draws from a shuffled bag of remaining indices (each track once per cycle; auto-advance stops when the bag empties, manual `>` refills), `prev_track` walks back through the actual play order; the bag resets when the playing playlist object changes. Emits `track_changed`, `track_finished`, `art_clicked`, `art_changed(QPixmap)`, and `play_state_changed(bool)`. All artwork must go through `player.set_art(pixmap)` (single image) or `player.set_art_gallery(paths)` so listeners stay in sync. The gallery is the album folder's images (cover first); `step_art(±1)` scrolls it, and every `AlbumArtLabel` registered via `register_art_label()` (player column, max view, mini view) gets hover arrows wired to it. Progress bar/time labels follow the same registration pattern: `register_progress_display(progress_bar, pos_label, len_label)` wires a `ClickableProgressBar` (max/mini mode's `ControlPanel`) to seek/resume and mirrors the player column's own bar/labels onto it from every mutation site (`_set_progress_value`/`_set_progress_text` — the single source of truth stays `check_track_pos`/`seek_to`/`load_track`). A big favourite heart (`heart_overlay`, an `overlay_controls.HeartOverlay`) is a child of `album_widget` shown only on hover (`Player.eventFilter` watches Enter/Leave/Resize on `album_widget`, since its child — the heart button — would otherwise swallow those events first). Wired by App to `_toggle_current_favorite`; `update_button_icons()` keeps its accent in sync. Progress/lyrics tick on a 200ms QTimer. SVG icon rendering is memoized by (name, color, size). Layout is pure Qt layouts, plus one deliberate exception: `resizeEvent` recomputes a `_compact_t` (0=tight..1=roomy) from the column's height and shrinks the controls block's margins/spacing/icon size/progress-bar thickness as it gets short, so the fixed-height controls never eat into the album art's space. `set_control_scale()` folds `_compact_t` into its icon-size formula (transport and toggle buttons both).

**`art_label.py`** — `AlbumArtLabel`: aspect-ratio-preserving art display. Downscales oversized sources (>1200px) once on load, caches a display-sized copy, and refreshes it on a 120ms debounce — no full-res repaints, no graphics effects. `square=True` center-crops sources to square (vinyl-sleeve feel; used by the player/mini art). Has built-in prev/next hover arrows for art galleries (`set_nav_enabled`) — shown only while hovered, hidden whenever the application deactivates.

**`theme.py`** — One font for the whole app: Inter, bundled in `src/fonts/` (Regular + Bold, OFL) and registered by `resolve_fonts()` at startup (system-sans fallback if missing). One size scale (`SIZES`/`DEFAULT_SIZE`) — the Text Size dialog and `Ctrl+=`/`Ctrl+-` step everything together. LIGHT/DARK token dicts (`bg`, `bg_elevated`, `fg`, `fg_dim`, `hairline`, `hover`, `accent`, `accent_fg`, plus legacy aliases for the dialogs). `build_qss()` produces ONE consolidated stylesheet applied once to the main window in `App.apply_theme` (theme/accent/font changes only). Focused-pane highlighting uses the dynamic `paneFocused` property on the tree/list views with `[paneFocused="true"]` selectors — focus changes repolish only the affected views, never regenerate QSS. `dialog_qss()` styles the dialogs. `track_list_qss()` factors out the `#track-list`/`#search-bar` rules so they can be applied standalone (not just as part of the one big stylesheet) when AlbumView is borrowed into MiniView, a separate top-level window the main stylesheet never reaches. `minimal_scrollbar_qss()` is a thin, fading, *square-cornered* scrollbar (both orientations — horizontal scrolling gets the identical treatment) used by the tracklist (always — it's folded into `track_list_qss()`), the lyrics pane in max/mini mode (see `lyrics_widget.py`), and the artwork-finder scroll areas; the base stylesheet hides scrollbars everywhere else. Accent color is woven into hover states everywhere (`accent_hover`, a ~9%-alpha tint, replaces flat grey hover on toolbar buttons and list/tree items) but is never trusted as literal text color at face value — `App.apply_theme` also computes `accent_text` (accent re-contrast-checked at ~4.5:1, stricter than the 3:1 used for `accent` itself) for the few spots that render it directly as foreground text (see `lyrics_widget.py`).

**`album.py`** — Parses a folder into a list of Track objects using mutagen for metadata and tinytag as fallback. `refresh_art()` scans the folder for artwork: `art` is cover.jpg, `art_list` is every image (cover first) — the scrollable gallery.

**`track.py`** — Plain data class for track metadata. All string fields are `str()`-converted in `__init__` to avoid mutagen lazy objects.

**`folder_view.py`** — Filesystem folder browser using QFileSystemModel. Filters to show only directories. Click loads a folder as an album in AlbumView. Has context menu for "Open folder" via platform file manager.

**`album_view.py`** — Tracklist. Long titles elide on one line (full text in tooltip); `setUniformItemSizes(True)` keeps large lists cheap. Loading an album selects row 0 so keyboard focus always lands on a visible highlight (App's `_focus_tracklist` also guarantees a selected row on Tab/`l`/`4`). Shows either an Album (`_on_album_loaded`, `★`-prefixed favourites) or a Playlist (`load_playlist`, labels carry the artist). Right-click a track for favourite/playlist actions (when `fav_store` is attached; emits `favorites_changed`) and "Look Up Chords / Tab", which opens the default browser (via `QDesktopServices`) with a web search — no scraping, no API key.

**`grip_splitter.py`** — `GripSplitter` (used for `main_splitter`/`right_splitter`) paints a faint 1px hairline along each handle's full length; the line turns accent-colored on hover.

**`progress_bar.py`** — ClickableProgressBar with click-to-seek and drag-to-scrub. Emits `seek_requested` (during drag) and `start_playback` (on release) signals.

**`music_icon_provider.py`** — Custom QFileIconProvider that hides folder icons (returns transparent pixmap) to keep the folder tree visually clean.

**`lyrics_widget.py` / `lyrics_fetcher.py`** — Lyrics display with synced scrolling; fetches from LRCLIB API, prefers synced `.lrc`, caches in `album/lyrics/`. The disk-cache check (and its `mkdir`) happens inside `LyricsFetchThread.run()`, never on the UI thread — the album folder is on a possibly slow NAS, and `App._on_track_changed` used to stat+read it synchronously per track change. Superseded fetches are disconnected and retired via `bg_threads` (see above), never `wait()`ed on. QTextBrowser-based: one QTextBlock per line/segment, active-line highlight via QTextCharFormat on only the changed blocks, auto-scroll from the block's measured y-position (accurate with wrapped lines). The active-line/timestamp color comes from `theme['accent_text']`, not `theme['accent']` — see `theme.py` — so it stays readable regardless of the chosen accent hue. Podcast descriptions get clickable timestamps and segment highlighting. Radio now-playing goes through `set_status_html()`. In max/mini mode the pane is short enough that scrolling isn't obvious, so App layers in `theme.minimal_scrollbar_qss()` (a thin, low-alpha handle that fades into the background) on top of the per-widget style override used there; the base app stylesheet hides scrollbars everywhere else.

**`artwork_finder.py`** — Artwork search dialog. iTunes Search API for covers, saved as `cover.jpg` (overwritten in place, streamed to disk). With `extra=True` ("Find More Album Art...") it saves to the next free `art_N.jpg` instead and *also* searches Discogs (`DiscogsSearchThread`, unauthenticated, ~4 requests/search against a 25/min limit) — Discogs releases carry collector scans of backs, labels, gatefolds and inserts, shown in their own section below the iTunes covers. In this `extra` mode each result row shows a checkbox instead of an immediate-save button; picks persist in `_selected` (keyed by URL) across repeated searches, and "Save Selected" downloads them all in one queued batch before closing the dialog — so you don't need a fresh dialog open per image. The non-extra ("Change Cover Art...") dialog keeps the original single-click-save-and-close flow. "Add Album Art..." (App) copies local image files into the album folder. All paths refresh the player's gallery. `finder_dialog_qss()` is the one stylesheet for these dialogs (rows opt in via object names: `#result-row` with accent-tint hover, `#row-thumb/-title/-detail`, `#accent-btn`, `#section-header`, `#status-label`, accent checkboxes, minimal scrollbar); radio's `StationArtDialog` reuses it, and in multi-select mode the whole row is a click target for its checkbox.

**`color_extract.py`** — Extracts a palette from album art (QImage pixel sampling, HSV binning) and picks the most readable accent color using WCAG contrast ratios. Always runs in `PaletteExtractThread` — never on the UI thread; the last palette is cached for menu rebuilds.

**`vim_views.py`** — VimTreeView/VimListWidget with vim-style j/k/h/l navigation, `/` search, and Enter-to-open. Consumes printable keys to prevent type-to-search.

**`play_log.py`** — Listening history: append-only JSONL (`<appdata>/plays.jsonl`, e.g. `~/.local/share/lp/music-player/` — deliberately Qt-free path logic so App, server threads, and the CLI agree) plus the pure `aggregate()` behind `/stats`. A play counts by the Last.fm rule (≥50% of the track or ≥4 min of *actual* listening): `Player._listened` ticks in `check_track_pos` only while playing (seek-immune), and `Player.flush_listen()` — first statement of `play()`/`load_track()`, plus once in `closeEvent` — emits `listen_ended(track, seconds)` which `App._on_listen_ended` gates (music only) and appends. Phone plays arrive via `POST /api/played` (same rule, client-side accumulator in webclient/app.js, single-fire beacon). `python src/play_log.py --stats 2026` / `--fake N --out F` for testing. Stats served at `/stats` (Preferences → Listening Stats... opens it; starts the server one-shot without flipping `server/enabled`): year-picker page, top artists (photos via `/api/artist_image` — Deezer, keyless, cached in `<appdata>/artist_images/` with `.miss` negative-cache), album grid from `/api/art`, bar charts in `#cc7511` (validated vs `#121212`; the app accent `#f2932c` is out of the dark-mode lightness band for data marks).

**Remote access deployment note**: the server itself is plain HTTP. HTTPS (and off-LAN access) comes from Tailscale on the host — `tailscale serve --bg 8642` proxies `https://<machine>.<tailnet>.ts.net/` → `127.0.0.1:8642` (tailnet-only, persists across reboots; `tailscale serve --https=443 off` disables). The HTTPS origin matters beyond transport: browsers treat the Media Session API (lock-screen art/controls) as secure-context-only, and the client additionally reports `mediaSession.playbackState` on play/pause — without it a paused session is treated as abandoned and the lock-screen play button reverts to the phone's previous media app. The phone must be on the tailnet (Tailscale app connected); plain-LAN http URLs still work for playback but with second-class lock-screen behavior.

**`media_server.py` / `server_dialog.py` / `webclient/`** — Remote Access (Preferences menu): an embedded stdlib HTTP server (`ThreadingHTTPServer` on a daemon thread — plain `threading`, never Qt; handlers only read disk via `Album`) that streams the library to a phone over LAN/Tailscale. Binds `0.0.0.0:<server/port>` (default 8642); auth is a short shared token as `?token=` (query param because `<audio src>` can't set headers), compared with `hmac.compare_digest`. Album ids are POSIX relpaths under `library_root`, containment-checked by `_resolve()` — absolute paths never cross the wire. `GET /api/favorite`/`POST /api/favorite` (query/body: `id`, `n` — album id + tracknumber) read/toggle favourite status against the same `favorites.json` the desktop app uses (`FavoritesStore`, constructed fresh per request rather than shared across threads); the track's real path is resolved server-side from `Album(folder).tracklist` by tracknumber, never trusted from the client. `/api/albums` is a stale-while-revalidate cached `os.walk` (a big NAS library can take ~35s to walk; requests never wait once warmed — `start()` pre-warms). `/api/stream` + `/api/art` do single-range requests (206/416, HEAD parity, 64 KiB chunks, abort-tolerant) — iOS Safari's `Range: bytes=0-1` probe must get a correct 2-byte 206 or audio silently fails. `webclient/` is a vanilla-JS PWA styled after mini mode: full-bleed letterboxed cover, translucent controls (incl. a favourite heart button, `refreshFavoriteState()`/`/api/favorite`) that auto-hide after 2.5s idle, library as a left drawer, tracklist as a right overlay. Screen-off album playback = ONE persistent `<audio>` element whose `ended` handler swaps src and replays (recreating the element drops iOS's background-audio session); Media Session API is feature-guarded (secure-context-only — absent over plain http, playback still works). `media_server.py` runs standalone for curl testing: `python src/media_server.py --root ~/Music --port 8642 --token test`. App owns start/stop (`_start_media_server`/`_stop_media_server`); autostarts when `server/enabled`, stops in `closeEvent`, follows library-root changes live. Note: `.m4a` files are listed by the walk but produce no tracks (`tracklist_from_folder` has no m4a tag branch), so m4a-only folders 404 — same as the desktop.

**Settings**: `QSettings('lp', 'music-player')` persists theme, accent (global + per-album `album_accents`), text size (`font_size`), overlay panel opacity (`overlay_opacity`, 0-100), whole-window opacity (`window_opacity`, 30-100 — "Window Opacity..." in Preferences; `setWindowOpacity` on the main window, mirrored onto the mini window), window geometry, panel layout (`layout/*` keys via PanelManager, incl. per-mode panel memory), mini mode state (`mini/*`), remote access (`server/enabled`, `server/port`, `server/token`), library path, app mode, shuffle, and per-mode playback positions. Favourites/playlists live in `<appdata>/favorites.json`, not QSettings.

## Keyboard Shortcuts

All global QShortcuts are suppressed when a QLineEdit has focus. Max mode handles its keys in `App.keyPressEvent`/`_dispatch_max_key` (also reachable via `App.eventFilter` when a borrowed widget has focus); mini mode via a key→handler map (`_keymap`) plus a modifier-sensitive `_shift_keymap` App gives the MiniView.

| Key | Action |
|-----|--------|
| `j` / `k` | Navigate down / up in focused pane |
| `h` / `l` | Folder view: collapse / expand; Tracklist: go to library |
| `Tab` | Switch focus between folder view and album view |
| `Enter` | Load album (folder view) or play track (tracklist) |
| `/` | Open search bar in focused pane |
| `p` | Play/Pause |
| `>` / `<` | Next / Previous track (podcast: ±30s) |
| `f` / `b` | Seek forward / back 5s |
| `.` / `,` | Volume up / down 5% |
| `1` / `2` / `3` | Switch to music / podcast / radio mode (same mode again: toggle library panel) |
| `0` | Switch to favourites mode (same again: toggle library panel) |

## Key Conventions

- Vim j/k/h/l navigation in folder view and tracklist; h/l in tracklist switches to folder view
- Global QShortcuts are suppressed when a QLineEdit has focus
- Panel visibility/sizes go through `PanelManager` only — never call `setVisible` or `setSizes` on the panes directly
- All artwork goes through `player.set_art()` / `player.set_art_gallery()`; theme/accent changes go through `App.apply_theme` (one stylesheet)
- One font (Inter) and one text size app-wide — no per-category font settings
- All source files live in `src/` with flat structure (no subpackages)
- No test suite exists currently
- Dependencies: PyQt5 for GUI, just_playback for audio, mutagen/tinytag for metadata, requests for API calls
